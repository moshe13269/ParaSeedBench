# ParaSeedBench

ParaSeedBench measures semantic consistency in text-to-image pipelines on a
crossed grid of meaning-equivalent prompt wordings and random seeds. The frozen
protocol uses four wordings and eight shared seeds per scene, reports correctness
alongside finite-grid wording, seed, and nonadditive-residual components, and
supports crash-safe restart.

This repository is the paper-aligned v0.3.0 release. It contains:

- the 96-scene main suite, 16-scene development suite, and four-scene smoke suite;
- every fixed seed and immutable Hugging Face model revision;
- Linux/RTX 6000 Ada and Windows 11/RTX 3070 profiles;
- resumable generation, semantic evaluation, DINO embedding, and analysis code;
- the completed two-rater audit labels and adjudication;
- CPU-verifiable paper artifacts and the final ICASSP LaTeX project;
- a compatibility snapshot for resuming the original v0.2.4 workstation run.

The published main run contains 11,520 images: 96 scenes × 5 prompts × 8 seeds ×
3 pipelines. The human-primary audit contains 1,536 images: 16 complete scenes ×
4 equivalent wordings × 8 seeds × 3 pipelines. Model weights and generated PNGs
are not committed to Git; the images are hosted separately (see below).

## Important v0.3.0 correction

The final paper defines held-out selected-worst accuracy, \(R_{ho}\), using all
35 unordered balanced splits of eight seeds, both train/test directions, and
averaging over tied worst wordings. The v0.2.4 source used only one even/odd split.
Version 0.3.0 corrects this analysis implementation and adds ordering/tie tests.
It does **not** invalidate or require regeneration of the v0.2.4 images, semantic
labels, decomposition, accuracy, agreement, or audit results.

The checked-in human audit is re-analyzed with the corrected definition and
reproduces the paper's \(R_{ho}\) values. The original full-suite automatic CSVs
are preserved as generated by v0.2.4; their legacy `crossfit_worst_accuracy`
column is not used in the paper. See [REPRODUCIBILITY.md](REPRODUCIBILITY.md).

## Quick verification without a GPU

Python 3.10 is the reference version; 3.10–3.12 are supported.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install --no-build-isolation -e ".[test]"
python -m pytest -q
python -m paraseedbench.verify_release
```

The final command checks frozen prompt hashes, seeds, artifact checksums, raw
rater/adjudication consistency, inter-rater statistics, and paper values. It does
not download a generator or regenerate images.

If Ubuntu lacks `ensurepip` and you have no `sudo`:

```bash
python3 -m pip install --user virtualenv
python3 -m virtualenv --system-site-packages .venv
source .venv/bin/activate
python -m pip install --upgrade pip "setuptools>=68" wheel
python -m pip install --no-build-isolation -e ".[test]"
```

## Linux workstation / RTX 6000 Ada

Install a CUDA-enabled PyTorch build compatible with the installed driver, or
retain the CUDA-enabled PyTorch already provided by the workstation. Then run:

```bash
source .venv/bin/activate
python -m paraseedbench.check_install
python -m pytest -q
```

`check_install` must print `CUDA available: True` and `NVIDIA RTX 6000 Ada
Generation`. A low GPU-utilization reading while checkpoints download or pipeline
components load is normal; GPU utilization should rise during the image tqdm.

Run the frozen smoke protocol first:

```bash
bash run_v2.sh configs/smoke_v2.lock.yaml
```

Run the full experiment after inspecting smoke outputs:

```bash
bash run_v2.sh configs/main_v2.lock.yaml
```

For an unattended SSH session:

```bash
nohup bash run_v2.sh configs/main_v2.lock.yaml > main_weekend.log 2>&1 &
echo $! > main_weekend.pid
tail -f main_weekend.log
```

This survives terminal/SSH disconnection, not a workstation reboot.

## Windows 11 / RTX 3070

In PowerShell, first check installed Python versions:

```powershell
py -0p
py -3.10 -m venv .venv
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip setuptools wheel
```

Install a CUDA-enabled PyTorch wheel using the command from the official PyTorch
selector, then install this project:

```powershell
python -m pip install --no-build-isolation -e ".[test]"
python -m paraseedbench.check_install
python -m pytest -q
.\run_v2.ps1 -Config configs\smoke_v2.lock.yaml
```

The RTX 3070 has 8 GB VRAM. Use the offload profile for a new full run:

```powershell
.\run_v2.ps1 -Config configs\main_v2_rtx3070.lock.yaml
```

Do not use the resident RTX 6000 Ada profile on the 3070. CPU/ offload makes
the 3070 run substantially slower and requires adequate system RAM.

## Where outputs are saved

By default, outputs are placed under the repository directory because each locked
configuration contains a relative `output_dir`, for example:

```text
outputs/v2_main_v030_rtx6000ada/
```

You may change only `output_dir` before starting a new run, including to an
absolute mounted-drive path. The output location is excluded from experimental
identity. Do not edit prompts, seeds,  settings, revisions, thresholds, or
source files during a run.

## Restart after interruption or power loss

Each PNG, per-image semantic score, and DINO batch is committed atomically and
validated before reuse. Re-running the same locked command skips valid completed
units. A denoising step in progress is recomputed.

After a restart:

```bash
cd /path/to/ParaSeedBench
source .venv/bin/activate
python -m paraseedbench.run_v2 --config configs/main_v2.lock.yaml --stage status
```

If and only if no old process is running, clear a stale writer lock:

```bash
pgrep -af 'paraseedbench.run_v2'
python -m paraseedbench.run_v2 --config configs/main_v2.lock.yaml --clear-stale-lock
bash run_v2.sh configs/main_v2.lock.yaml
```

The clear command removes only `.run.lock`; it does not delete images or scores.
Never run two writers against the same output directory.

## Restore the completed v0.2.4 experiment

If the original `outputs/v2_main_v024_rtx6000ada` directory still exists on the
workstation or Drive, do not rerun 11,520 images.

1. Copy the entire output directory, its original `configs/main_v2.lock.yaml`, and
   `run_manifest.json` together.
2. To resume unfinished v0.2.4 generation/evaluation, extract
   `compatibility/ParaSeedBench_v0.2.4_Linux_RTX6000Ada.zip` and use that source.
   Its SHA-256 is
   `3ae0c4f98ef1b056ea7688acefbf4906186ef6e0baab2923e7b107509c9f8104`.
3. To recompute derived automatic tables with v0.3.0 while preserving the originals:

```bash
python -m paraseedbench.reanalyze_v2 \
  --input /path/to/outputs/v2_main_v024_rtx6000ada \
  --dataset data/scenes_v2_main.jsonl
```

4. To regenerate corrected human summaries, run the v0.3.0 audit scorer against
   the existing audit directory and the completed A/B/adjudication files.

The re-analysis command writes `analysis_v030` and never modifies images,
`semantic_scores.csv`, DINO embeddings, or the original `analysis` directory.

## Human audit workflow

Create a new prespecified audit from a completed main run:

```bash
RESULTS_DIR=outputs/v2_main_v030_rtx6000ada
python -m paraseedbench.audit_v2 \
  --input "$RESULTS_DIR" \
  --output "$RESULTS_DIR/audit" \
  --scenes-per-category 4 --seed 2027
```

Serve the viewer from the run directory:

```bash
cd "$RESULTS_DIR"
python3 -m http.server 8000
```

Open `http://localhost:8000/audit/index.html`. Raters A and B see the same images
and atom requirements but receive separate CSVs. They must not see each other's
labels or `PRIVATE_machine_key.csv` before both files are complete. Preserve
`human_atom_state` as text so leading zeros remain intact. Full instructions are
in [docs/ANNOTATION.md](docs/ANNOTATION.md).

After independent labeling:

```bash
python -m paraseedbench.audit_v2 \
  --input "$RESULTS_DIR" --output "$RESULTS_DIR/audit" \
  --human "$RESULTS_DIR/audit/human_a.csv" \
  --second-human "$RESULTS_DIR/audit/human_b.csv"
```

If blocked, fill only the disagreement rows in `human_adjudicated.csv`, then run:

```bash
python -m paraseedbench.audit_v2 \
  --input "$RESULTS_DIR" --output "$RESULTS_DIR/audit" \
  --human "$RESULTS_DIR/audit/human_a.csv" \
  --second-human "$RESULTS_DIR/audit/human_b.csv" \
  --adjudicated-human "$RESULTS_DIR/audit/human_adjudicated.csv"
```

## Paper and released evidence

- `manuscript/main.tex` is the Overleaf entry point.
- `manuscript/ParaSeedBench_ICASSP2027.pdf` is the compiled five-page artifact
  (four technical pages plus references).
- `paper_artifacts/automatic_main/` contains the 96-scene automatic diagnostics.
- `paper_artifacts/human_audit/` contains raw A/B labels, disagreement-only
  adjudication, the post-unblinding audit key, and corrected derived summaries.
- `paper_artifacts/SHA256SUMS` protects every released evidence file.

Run `python -m paraseedbench.verify_release` before a paper or code release.

## Scientific scope

The components are exact descriptions of a finite binary response table, not
unbiased random-effects variance estimates. With one generated image per
wording–seed cell, nonadditive residual variation cannot be separated from cell
noise or judging error. Seeds are shared across wordings within each pipeline;
equal integer seeds are not common semantic latents across architectures.
Automatic OWLv2/CLIP scores are secondary because evaluator error was
generator-dependent. The 16-scene adjudicated audit is primary but still small.
